项目简介

moonbit-casbin 是使用 MoonBit 实现的 Casbin 风格授权引擎，填补 MoonBit 生态在模型驱动访问控制上的空白。传入模型文件与策略文本即可完成访问判定：判定规则写在模型里（请求、策略、角色定义，effect 聚合方式，matcher 表达式），具体权限写在策略行里（p 行、g 行），更换模型即可在 ACL、RBAC 等风格之间切换。交付内容覆盖模型解析、自研 matcher 表达式引擎、完整判定链路、RBAC 与策略/角色管理 API、全套内置匹配函数。

通用性说明

授权判定与具体业务无关，凡是需要判断“谁能否对什么做什么”的项目都可以直接复用；模型与策略格式与 Casbin 生态一致，已有模型和策略文件可以平移使用；库不读写文件、不联网，模型与策略文本由调用方提供，服务端、浏览器与边缘（wasm/js）都能使用；matcher 函数注册表开放，可按业务补充自定义函数；仅依赖 MoonBit 标准库与官方 moonbitlang/regexp，四个后端一致可用。

预期使用场景

  1. 1. Web 接口权限校验：r = sub, obj, act 对应“用户、接口路径、HTTP 方法”，策略行按角色授权（如 p, data2_admin, /api/data2/:id, GET），matcher 用 g(r.sub, p.sub) && keyMatch2(r.obj, p.obj) && regexMatch(r.act, p.act)；每个请求调用 enforce，true 放行、false 拒绝。
  2. 2. 多租户角色隔离：g = _, _, _ 把角色绑定到租户域（如 g, alice, admin, tenant1），matcher 用 g(r.sub, p.sub, r.dom) && r.dom == p.dom，租户之间互不影响；运行期用 add_role_for_user、delete_role_for_user 调整授权。
  3. 3. 管理后台权限页：用 get_policy、get_filtered_policy 渲染策略表格，用 add_policy、remove_filtered_policy 处理增删改，用 get_implicit_roles_for_user、get_implicit_permissions_for_user 展示用户的全部权限，用 delete_user、delete_role 做级联清理。

拟实现的核心功能

  • 模型配置解析与校验：五类节、token 校验，六类结构化错误（带行号或字符偏移）；
  • matcher 表达式引擎：词法、Pratt 语法与求值，支持布尔短路、in 列表、字段访问、算术与字符串拼接，函数可注册；
  • 判定链路：内存策略存储（保序、去重）、CSV 策略解析、5 种 effect 聚合、逐行匹配与提前终止；
  • RBAC：角色层级（含层级上限）、角色域、g / g2 注入、策略变更后角色链接自动重建；
  • 管理 API：策略与角色增删查、隐式角色与隐式权限、级联删除；
  • 内置匹配函数：keyMatch / keyGet 系列、regexMatch、globMatch、ipMatch（IPv4/IPv6 + CIDR）。

移植或参考说明

  • 参考项目：Casbin，https://github.com/casbin/casbin ，许可证 Apache-2.0（本项目采用同一许可证）；
  • 实现方式：从零手写约 6700 行 MoonBit，不复制、不翻译 Go 源码；移植的测试用例表在 THIRD_PARTY_NOTICES.md 中逐项注明来源；唯一运行时依赖为官方 moonbitlang/regexp（Apache-2.0）；
  • 边界与简化：不实现 Go 反射式 ABAC、eval()、条件角色、EnforceContext、Watcher 与数据库适配器，角色名模式匹配暂不支持（README 已列明）。
